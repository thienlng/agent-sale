## Root cause and changes

Independent QA inspected live tag schemas read-only: Event requires event_name, Ticket requires subject, and VIP has no required field. Inbox formerly sent only tagId, reproducing backend rejection for Event/Ticket. The shared values form is extracted from CRM into the application component layer; no feature imports another feature. Conversation tags remain conversation-scoped and customer tags are not silently merged into them. No live customer records were modified during diagnosis or testing.

QA also found and the implementation fixed: implicit null-bot submission from Assign bot, inconsistent unassigned filters, stale inbox availability after toggles, editable page checkboxes during saving, and mobile toolbar clipping hidden by an overflow container. The latter now has direct control-bounds coverage, not only document overflow assertions.
