# identity

**Purpose:** users, password login, sessions (refresh-token rotation) and access tokens; owns the single global `AuthGuard` that authenticates every non-public route and enforces workspace membership on `@WorkspaceScoped()` routes.

**Owned tables:** `users`, `sessions` (global, app_system only — migration 0001), `user_mfa` (migration 0018), `email_codes` (migration 0056), `user_identities` (migration 0072), `auth_counters` and `trial_claims` (migration 0076; schema in `packages/db/src/schema/identity.ts`).

**Public API (`api/`):** `IDENTITY_FACADE` (bootstrap helpers; `profile(userId)` → `{ name, email, locale }` with `locale` `vi` unless the user chose `en`, used by `notification` for the recipient's address and language, T-172) and, for the platform admin only, `IDENTITY_ADMIN_FACADE` → `usersByIds(ids)`, `searchUsers(q, limit)` (email/phone/name substring) returning `{ id, name, email, phone }`. `IDENTITY_DELEGATION_FACADE` → `delegate(authorization, ttlSeconds)`: a short-lived (≤ 10 min) access token of the same user and session, claim `dlg`, for the owner assistant's in-process route calls that may outlive the caller's token (ADR-024); a delegated token cannot be delegated again. Other modules use `@Public()`, `@WorkspaceScoped()`, `@CurrentUser()`, `@CurrentWorkspace()` from `common/http/auth-context.ts`. HTTP: `/auth/signup|login|refresh|logout`, `/auth/signup/code`, `/auth/signup/business`, `/auth/password/forgot|reset`, `/auth/providers`, `/auth/google/start|callback|mfa`, `/me`, `/bootstrap`, `/auth/mfa`, `/auth/mfa/setup|enable|disable|recovery-codes` (contracts in `packages/contracts/src/identity/`).

**Events consumed:** none. Uses the `workspace` facade (create the first business in onboarding, membership lookups), the `billing` facade (the first business starts the account's trial; a failure is logged and never blocks it), the `MAILER` port (`common/email`, Resend in production) and the `account` facade (bootstrap lists the user's accounts and the account name of every business, so the web groups businesses by account; a member sees the owning account's name, nothing else about it).

**Invariants:**

- Passwords: Argon2id; 8–128 chars; not common; not equal to email/name. Unknown email and wrong password give the same error and cost the same time.
- Access token: EdDSA JWT, 15 min, claims `sub` (user) + `sid` (session). Refresh token: 32 random bytes, stored only as sha256, 30 days, rotated on every use; presenting a retired token revokes the whole family.
- Web clients get the refresh token only as an HttpOnly cookie scoped to `/api/v1/auth`; cookie refresh checks `Origin` against `APP_ORIGINS`. Native clients use the body (`client: native`).
- A workspace the user is not a member of answers 404, never 403, with `details.reason = 'workspace_access'` so the client can tell a lost business from a missing resource (it reloads bootstrap; T-079). The reason reveals nothing: the same answer is given whether the workspace exists or not.
- Platform admin (`users.is_platform_admin`) is set only by the CLI (`pnpm --filter @agent-sales/backend platform-admin grant|revoke <email>`), exposed read-only as `UserDto.isPlatformAdmin`, and re-checked in the database on every `@PlatformAdmin()` request (non-admins get 404).

- **Two-factor (ADM-04):** TOTP (RFC 6238, SHA-1, 30 s, 6 digits, ±1 step). The secret is sealed with `SecretBox` (`SECRETS_ENCRYPTION_KEY`); recovery codes (8, `xxxxx-xxxxx`) are stored only as sha256. A setup is pending until the first valid code; only then does login ask for a second factor. A code is accepted once (`last_used_step` advanced atomically); a recovery code is burned atomically. Login without a code answers 401 `details.reason = mfa_required`, a wrong one `mfa_invalid`; the per-IP+email attempt counter is only reset after the second factor passes. Setup needs the password; disabling and replacing recovery codes need password + a current code (400 `invalid_password|invalid_code`, not 401, so the session survives). Lost phone and codes: operator runs `pnpm --filter @agent-sales/backend mfa-reset <email>`.

- **Email verification (ACC-01, ADR-023):** `/auth/signup/code` (public, rate-limited per IP) emails a 6-digit code (sha256 of email + purpose + code in `email_codes`, 15 min, 5 wrong tries then `code_expired`, a new code at most every 60 s → 429 with `retryAfterSeconds`). `/auth/signup` needs the code (400 `code_invalid|code_expired`) and creates the user verified, with no business. `/auth/signup/business` creates the first account + business + trial, 409 `account_exists` once the user owns an account.
- **No signup enumeration (migration 0076):** `/auth/signup/code` answers 204 for a registered address too; that address gets `accountExistsEmail` (no code) and a decoy code row is stored, so cooldown, caps and wrong-guess answers look the same. `/auth/signup` consumes the code before checking the email, so 409 `email_taken` is left only for a race. The `name` field is ignored; code emails never carry requester text.
- **Auth counters (`WindowCounter` port, `AUTH_COUNTER`, `application/auth-limits.ts`):** fixed windows shared by every replica (`PostgresWindowCounter` on `auth_counters`, sha256 keys; in-memory without a database). Code emails: 3 per address per hour, 5 per day (429). Code checks: 20 per address and purpose per day across resends (429 `TOO_MANY_ATTEMPTS`; the 21st reset check emails the owner `codeGuessAlertEmail` once). Login: 20 per normalized email per hour on any IP (429), cleared by a successful login or password reset; the per-IP+email `AttemptLimiter` stays.
- **One trial per person (`domain/trial-identity.ts`):** the first business starts the trial only if the owner's canonical email (lower case, no `+tag`; Gmail without dots, `googlemail.com` → `gmail.com`) is claimed in `trial_claims` for that user and the domain is not disposable (built-in list + `TRIAL_BLOCKED_EMAIL_DOMAINS`). The account is created either way.
- **Password reset:** `/auth/password/forgot` answers 204 for any email (no enumeration; rate-limited per IP); `/auth/password/reset` (rate-limited per IP + email) checks the code and the password policy, sets the password and revokes every session of the user.

- **Google sign-in (ADR-007, `application/google-sign-in.ts`, `interface/http/google-auth.controller.ts`):** authorization code + PKCE (S256) + `state` + `nonce`, run on the server. `/auth/google/start?redirect=` seals `{state, verifier, nonce, redirect, exp}` with `SecretBox` into the cookie `rapiz_google` (HttpOnly, SameSite=Lax, path `/api/v1/auth/google`, 10 min) and redirects to Google. `/auth/google/callback` checks the state against the cookie (constant time), exchanges the code, verifies the ID token with Google's keys (`HttpGoogleOAuthClient`: issuer, audience, RS256, required `exp`/`iat`/`sub`, 30 s clock tolerance; logs only Google's token-endpoint `error` word or jose's error code), the nonce and `email_verified`, then resolves the user: linked `sub` → that user; else the user with the same email, only when Google is authoritative for it (`@gmail.com`, or `hd` claim = the address's domain; otherwise `account_exists`), and an unverified one loses its password and every session; else a new password-less, verified user. Every completed sign-in upserts `user_identities` (a `sub` linked to another user is never moved). With TOTP on, a sealed 5-minute ticket (carrying the pending link) goes to `rapiz_google_mfa` and `POST /auth/google/mfa` (Origin-checked) needs a code; the link and the unverified-address claim are applied only after it; else the refresh cookie is set. The browser always lands on `/login` with `google=done|mfa` or `google_error=cancelled|expired|unverified_email|account_exists|unavailable|too_many|failed` and `redirect` (same-app paths only: no `//`, backslash, space or control character). Callbacks with a live flow are rate-limited per IP on `GOOGLE_CALLBACK_LIMITER` (60 per 15 min, reset by a completed sign-in). Unexpected errors are logged as class name + SQLSTATE, never the message. Password login of a password-less user fails like a wrong password, at the same cost. Config: `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET` (both or neither; unset → `/auth/providers` says `google: false`), `GOOGLE_REDIRECT_URI` (default first `APP_ORIGINS` + `/api/v1/auth/google/callback`).

**Do not:** read `users`/`sessions` with the tenant connection; log tokens or passwords; add a second global guard.

**Test:** `pnpm --filter @agent-sales/backend test -- identity` and `pnpm test:integration`
